# 🛠️ Технічна підготовка даних та моделювання

Звіт з аналізу доходу, асортименту та купівельної поведінки клієнток, а також звіт з RFM-аналізу базуються на **єдиній реляційній моделі даних**. Процес обробки, трансформації, розрахунків та структурування рознесений по трьох послідовних кроках: **SQL**, **Power Query** та **Power BI**.

---

### 1. Етап SQL (Первинна обробка та PostgreSQL)
У SQL-коді виконано первинні розрахунки, консолідацію даних та агрегацію за допомогою складних запитів, зокрема CTE (*Common Table Expressions*) та віконних функцій. 
*   **Розрахунок показників клієнтської активності:** обчислено точні дати першої та останньої покупки для кожного клієнта, загальну кількість успішних замовлень, сумарний виторг (Monetary), індивідуальні часові інтервали між покупками та середній чек кожної клієнтки.
*   **Розрахунок RFM-показників:** сформовано базові оцінки давності (*Recency*), частоти (*Frequency*) та фінансової цінності (*Monetary*). На основі цих метрик реалізовано логіку розподілу клієнток за фіксованими бізнес-сегментами (`RFM_Group`).

*Примітка: Повний SQL-код додано до кореня репозиторію окремим файлом.*

---

### 2. Етап Power Query (ETL-процес)
На етапі ETL-трансформації в Power Query проведено фінальне очищення даних та розраховано додаткові аналітичні стовпці:
*   Створено групування та класифікацію даних, необхідні для коректної побудови та фільтрації фінальних графіків у звітах.
*   Оптимізовано типи даних та структурувано зв'язки для безшовної інтеграції таблиць із PostgreSQL у модель Power BI.

---

### 3. Етап Power BI (Архітектура моделі даних)
Фінальна аналітична архітектура налаштована безпосередньо всередині Power BI за допомогою мови розрахунків DAX:
*   **Structuring the model (Структурування моделі):** створено виділену технічну таблицю `_DAX_measures`. Вона використовується для централізованого зберігання, ізоляції та логічного групування всіх створених мір проєкту в одному місці, що спрощує підтримку моделі.
*   **Dynamic analysis (Динамічний аналіз):** впроваджено таблицю параметрів (`MetricSelector`). Це дозволило реалізувати інтерактивне перемикання між різними бізнес-метриками на одному й тому самому графіку без перевантаження інтерфейсу.
*   **Calculated columns (Розрахункові стовпці):** створено внутрішні розрахункові стовпці через DAX безпосередньо в моделі даних для забезпечення додаткових аналітичних розрізів під час фільтрації.
